## 1. 方針

- **E2E(`L1-Exx`)**: 一時ディレクトリに作った実 git リポジトリ(`base` と `head` のコミット)を入力に、`gov` の入口(CLI、フック、GitHub Action のエントリ)の出力と終了コードを確かめる。内部関数は呼ばない。フックは実機の `claude -p` でも 1 件確かめる(E21)。 [推論]
- **構造検査(`L1-Sxx`)**: 依存の向き、`Repo` 以外から読まないこと、設計と実装の一対一を、ソースの静的検査で確かめる。
- **設定の検査(`L1-Cxx`)**: GitHub 側の設定を読み取って確かめる。
- テストの追跡は、`design` marker を使わない。このリポジトリ自身の E2E テストは、v2 の要件(例: `REQ-2026-010`)の機能タグ(`REQ-2026-010-Fnn`)を `requirement` marker に付ける。設計書の項目と機能タグの対応は §5 の追跡表で持つ。 [推論: 第4版 F8 への対応]
- ディレクトリは E2E が `tests/e2e/`、構造検査が `tests/unit/` または `tests/integration/`(D10 で確定)。 [原典: オーナーの全体方針]
