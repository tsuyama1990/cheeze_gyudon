## 1. 方針

- **E2E(`L1-Exx`)**: 一時ディレクトリに作った実 git リポジトリ(`base` と `head` のコミット)を入力に、`gov` の入口(CLI、フック、GitHub Action のエントリ)の最終出力と終了コードを確かめる。内部関数は呼ばない。 [推論]
- **構造検査(`L1-Sxx`)**: 設計書の構造上の主張(依存の向き、純粋性、一対一)を、ソースの静的検査で確かめる。E2E ではない。
- **設定の検査(`L1-Cxx`)**: GitHub 側の設定(保護ルール、テンプレート、ワークフロー)を読み取って確かめる。ローカルでは再現できない。
- 設計書の項目を指す marker は、要件の marker(`requirement`)と名前空間を分ける(`@pytest.mark.design("L1-E03")`)。 [推論: Opus M5 への対応。D10 で確定]
- ディレクトリは E2E が `tests/e2e/`、構造検査が `tests/integration/` または `tests/unit/`(D10 で確定)。 [原典: オーナーの全体方針 `tests/e2e|integration|unit/`]
- 規約 C1〜C3 は人間の運用でテスト対象外。ただし、種別「検証機構」「決定」の PR で、人間のマージが必要であることを出力に明示する点は E15・E20 で確かめる。
