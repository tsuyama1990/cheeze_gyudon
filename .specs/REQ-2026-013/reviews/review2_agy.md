**具体的にAIが暴走・不要停止する穴 (8件):**
1. `scripts/gate.sh` や CI 定義の無力化を「可逆」と判断して独断変更する。
2. 外部パッケージ（`uv add`）を無断追加し、サプライチェーン汚染を招く。
3. 未マージのローカルブランチを `git branch -D` で削除し履歴を不可逆喪失させる。
4. 起草中の要件定義から困難な非機能要件をAIが勝手に削って「進める」。
5. push で「まだしない」選択後、再質問禁止のため後続が base 不一致で永久膠着する。
6. 単なる外部Web検索やcurl参照を「外に出る」と誤判定して人間を過剰に止める。
7. 未追跡ファイルや未コミット変更を `git clean -fd` 等で不可逆破棄する。
8. 他リポジトリのフィーチャーブランチで共通規則を勝手に書き換えて破壊する。

## 3. 自己承認・形骸化のリスク
- **AIの自己承認**: 台帳の `AI` → `有効` の遷移は文章規則（N1）頼み。AIがコミットメッセージに過去の回答を適当に引用して自己承認を偽装可能。
- **1タップの橡皮印化**: 人間に「承認(推奨)」の1問を出す際、差分要約がないと人間は内容を見ずに推奨を押す。AIが直前に混入させた欠陥も素通りする。
- **AskUserQuestionの自動化**: Subagentやバッチ環境では質問が上位AIに吸い上げられ、人間の実質的意思表示なしに承認コミットが偽造される。

## 4. 事例の検証 (事例2: K.c 停止の解決経路)
- **制約遵守**: **違反疑い大**。ローカルで既に010を閉じた決定（`d5074a6`）が存在するのに、「origin/mainではまだopen」を口実に過去に遡ってテストを変更するのは、因果の逆転であり [DEC-043](file:///home/tomo/project/cheeze_gyudon-decide/.specs/REQ-2026-010/decisions.md#L248)（閉じた要件のテスト保守はopenに戻して行う）の脱法である。
- **rebaseと承認の意味**: 人間の決定コミット `d5074a6` の位置とハッシュが変わることは、承認当時の前提ツリーを破壊する。「同意の記録の並べ替え」を1問で済ませるのは承認の厳密性を損なう。

## 5. 代替案 (より少ない仕組みで目的を達成)
- **案A: 境界2点（Push/Merge）関所型 + ローカル完全自律**
  - 台帳（`decisions.md` のAI列）を全廃。ローカルでの試行・変更は自由。エスカレーションは「リモートPush」と「mainへのPRマージ」の2点のみ。
  - *Pro*: プロトコルが20行以下になり形骸化ゼロ。 *Con*: 大幅な方針脱線時の手戻りコスト増。
- **案B: 隔離ブランチ（try/*）によるリアルオプション運用**
  - 不確実な判断は台帳に書かず `try/<req>-<topic>` ブランチに隔離実装。差分要約とともに1問で本流合流を問い、採否を決める。
  - *Pro*: Gitブランチ自体が台帳・リアルオプションとなり完全可逆。 *Con*: ブランチ管理手数が増加。
