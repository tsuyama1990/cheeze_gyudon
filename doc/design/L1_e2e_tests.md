このテスト計画は、設計書の不変条件(G1〜G4、I1〜I3)とフロー(§6)を、リポジトリ全体を通した振る舞いとして確かめる。

根拠の種類: **[原典]** / **[データ]**(2026-10-27 実測) / **[推論]**

## 1. 方針

- E2E は、一時ディレクトリに作った git リポジトリ(実ファイル、実 git)を入力に、`gov` の導出・検査の最終出力を確かめる。内部関数は呼ばない。 [推論]
- 判定が必要な GitHub 側の動作(必須チェック、承認)は、ローカルでは再現できない。そのシナリオは「検査が返す結果」までを E2E で確かめ、GitHub の設定そのものは **設定の検査**(テンプレートの内容と適用状態の確認)として別に扱う。
- すべてのテストに、設計書の項目を指す `@pytest.mark.requirement("L1-xxx")` を付ける。ディレクトリは `tests/e2e/`。 [原典: オーナーの全体方針 `tests/e2e|integration|unit/`]
