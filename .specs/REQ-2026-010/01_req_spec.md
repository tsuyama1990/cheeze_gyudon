# [REQ-2026-010] jtc-gov v2: 承認された設計だけが `main` に入る

この文書が、要件・範囲・保証・非保証・前提の正本。設計は [02_system_design.md](02_system_design.md)、決定は [decisions.md](decisions.md)、進め方と進行は [spirals.md](spirals.md)。

根拠の種類: **[原典]** / **[データ]**(実測。値の正本は [background/as_is_inventory.md](background/as_is_inventory.md)) / **[推論]** / **[決定]**(DEC-ID で参照)

## 1. 目的
AI エージェントが、人間が承認していない設計のまま、新しい挙動を `main` に入れることを防ぐ。 [決定: DEC-001]

## 2. 範囲
**含む(MVP)**: 承認マニフェストによる鍵(K)、決定 PR の検査(D)、タグの整合(T)、品質検査(Q)、Claude Code のフック(commit、push、Stop、通知)、状態の導出と表示、検証機構の変更の明示、情報の正本、ゲートの入口の一本化。
**含まない**: scaffold、Review / red team、PR コメント、テスト本体のハッシュ固定、エスカレーション記録、ゲート順序の CI 強制、PR の 5 種別、PostToolUse フック、`index` ref、Phase 5、`sandbox/`、PR サイズ上限、速度要件、Windows のパス区切り、自作の重複検出、`doc_sync_guard`、複数要件の並行。 [決定: DEC-017、DEC-014、DEC-016、DEC-019]
**対象リポジトリ**: 公開リポジトリ。保護ルールは、公開か有料プランでのみ作れる(無料の非公開では 403)。 [データ]

## 3. 保証・非保証・前提

**保証の境界**: `main` に到達するもの。ローカルの作業ツリーは保証しない。 [決定: DEC-001]

| ID | 保証(G) |
|---|---|
| G1 | 承認された設計がなければ、新しい挙動(`src/` の変更に、テストまたは仕様の変更が伴うもの)は `main` に入らない |
| G2 | 承認の作成・閉鎖は、設計がそろい、承認と内容が一致していることを確認してからでなければ通らない |
| G3 | テストは要件に紐づく(`requirement` marker)。紐づく仕様が存在する |
| G4 | 品質検査(lint、型、デッドコード、テスト、カバレッジ、変更行のカバレッジ)に通らないものは `main` に入らない |

| ID | 非保証(N) |
|---|---|
| N1 | ローカルの作業ツリーと、`git commit` を経ない書き込み。ローカルのフックは助言 |
| N2 | `src/` だけの変更が、テストの検出しない挙動を変えること [決定: DEC-023] |
| N3 | 承認した人が本人であること(A1 が未成立) |
| N4 | `src/` の外に置かれたコード |
| N5 | シェル経由の書き込み(D5 は未決。推奨は「保証しない」) |

| ID | 前提(A)。いずれも現状は未成立 |
|---|---|
| A1 | エージェントの資格情報が、承認・管理権限を持たない。現状は同一アカウント。MVP は未成立のまま許容する [決定: DEC-007] |
| A2 | `main` が保護され、必須チェックと PR が強制される。現状は保護なし |
| A3 | CI が、PR が書き換えられないチェッカーで判定する。現状は PR 側のチェッカーが実行される。規約 C2・C3 で補う [決定: DEC-004] |

## 4. 要件

- **[REQ-2026-010-F01] 鍵 K**: `src/**` と、`tests/**` または `.specs/**` の両方を変更する PR、またはテスト関数を足す・変更する PR は、有効な承認がちょうど 1 つあり、承認済みのファイルを変更せず、変更するテストと仕様が承認の要件の中にあるときだけ通る。
- **[REQ-2026-010-F02] 決定 D**: `approval.json` を変更または削除する PR は、状態ごとの条件(`open` は設計の成果物がそろいハッシュが一致、`closed` は仕様の全機能タグにテストがある、`withdrawn` は条件なし)を満たし、`open` が 2 つ以上にならないときだけ通る。
- **[REQ-2026-010-F03] タグの整合 T**: すべてのテスト関数は、形式が `REQ-YYYY-NNN-Fnn` の `requirement` marker を持ち、その要件の仕様が存在してタグを含む。テストのファイルは `tests/` にある。
- **[REQ-2026-010-F04] 品質検査 Q**: lint、型、デッドコード、テストの合格、カバレッジ、`src/` の変更行のカバレッジが、`pyproject.toml` の設定値以上でなければ通らない。新しい `# pragma: no cover` は通らない。
- **[REQ-2026-010-F05] フック**: Claude Code のフックが、コミット時(作業ツリー)と push 時(HEAD)に検査を実行する。K と D の違反は拒否し、T と Q.pragma の違反は警告にとどめる(CI が止める)。書き込み時、セッション開始時、指示のたびには状態を通知する。終了時の検査は、全体設定の `Stop` フックが `scripts/gate.sh` を呼ぶことで行う。
- **[REQ-2026-010-F06] 状態の導出と表示**: 現在ゲート、承認の有効/失効は保存せず、`main` の内容から導出して表示する。`state.json` を書かない。
- **[REQ-2026-010-F07] 検証機構の変更の明示**: 検証機構と `approval.json` を変更する PR は、出力に「人間のマージが必要」と表示される。
- **[REQ-2026-010-F08] 情報の正本**: 同じ情報を 2 か所に書かない。正本の一覧は [02_system_design.md](02_system_design.md) §2.1。規範の文書(01、02、AGENT.md、README)とコードのコメントでは、閾値の数値を複製しない。記録(decisions.md、reviews/、background/)は、当時の値を日付つきの事実として書いてよい。 [決定: DEC-025]
- **[REQ-2026-010-F09] ゲートの入口の一本化**: 品質ゲートの入口は `scripts/gate.sh` だけ。CI は、それを呼ぶ(全体設定のフックとマージスクリプトも呼ぶが、リポジトリの外なので検査しない)。pre-commit は衛生フックだけを持つ。`gov doctor` が、リポジトリ内の配線(CI、pre-commit、`.claude/settings.json`、`gate.sh`)を検査する。

## 5. 進め方
スパイラル開発。設計の変更は、パッチではなく、新しいスパイラル(目的・リスク・設計書の更新・レビュー・承認)として行う。定義と進行は [spirals.md](spirals.md)。 [決定: DEC-024]
