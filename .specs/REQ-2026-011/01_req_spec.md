# [REQ-2026-011] 運用規則の一本化: 規則は AGENT.md に置き、強制は届く場所に置く

この文書が、要件・範囲・保証・非保証・前提の正本。設計は [02_system_design.md](02_system_design.md)、決定は [decisions.md](decisions.md)、積み残しは [backlog.md](backlog.md)、検証の記録は [reviews/](reviews/)。

根拠の種類: **[原典]**(コード・規則・決定の文面) / **[データ]**(観測。日付つき) / **[推論]**(未検証) / **[決定]**(DEC-ID)

## 1. 目的
AI エージェントが運用規則を知らない、または知っていても守らない状態を減らす。規則を各リポジトリの AGENT.md に置いて、どのエージェントにも届くようにし、機械で止められるものは止める。止められないものは、止められないと明記する。 [決定: DEC-047]

動機: matome の `summarize` の開発(2026-10-29)で、次の 4 件が起きた。 [データ: 2026-10-29 の作業]
1. テストがコードより後に書かれた。
2. 承認済みの詳細設計と実装が食い違った。
3. bonsai が実施されなかった。
4. エージェントが `approval.json` を作成できた。

## 2. 範囲
**含む(MVP)**: 共通規則表を各リポジトリの AGENT.md に手で置く(コードなし)、Claude のグローバル PreToolUse フックの置き換え(`gov hook global-guard`)、マージスクリプトのメッセージ検査、`~/.claude/CLAUDE.md` の整理。
**含まない**: 規則表の雛形化と配布・検査(`gov init`/`gov doctor`。B-09)、ターン単位の Stop 検査(B-10。Stop は現行の `stop_gate.sh` のまま)、git のフック(pre-push、pre-merge-commit、commit-msg)、コミット履歴の順序検査、設計書と実装の機械的な一致検査、Stop での main 先行ブランチの検査、委譲時の worktree の強制、`gov` へのマージスクリプトの移設、資格情報の分離。理由は [02_system_design.md](02_system_design.md) §7 と [backlog.md](backlog.md)。 [決定: DEC-048、DEC-049、DEC-053]

## 4. 機能要件

- **[REQ-2026-011-F01] 共通規則表**: cheeze_gyudon と matome の AGENT.md に、規則 R01〜R18 を ID と強制の置き場つきで、エージェント非依存の文面(ツール名を含まない)の表にして置く。印(`<!-- gov:rules v1 -->` … `<!-- /gov:rules -->`)で囲む(将来の検査用。B-09)。手で書く。matome には CLAUDE.md(「規則は AGENT.md にある」の 1 行)も置く。
- **[REQ-2026-011-F04] 対象リポジトリの解決**: グローバルの PreToolUse フックは、Bash の `git` 呼び出しの対象リポジトリを、`git -C <dir>` と `cd <dir> &&` から解決し、解決できなければ cwd を使う。Edit/Write は編集先のパスから解決する。main/master への直接のコミットと編集を拒否し、`git add -A`/`--all`/`.` を拒否する。
- **[REQ-2026-011-F05] 人間の確認と main 上の merge の拒否**: 次を ASK(人間の承認を挟む)にする: `.specs/*/approval.json` への Write/Edit、`approval.json` と書き込み系の語を含む Bash、`git push`、`merge-to-main.sh` の実行。現在のブランチが main/master である対象への `git merge` を拒否する(作業ブランチで `git merge main` を取り込む操作は通す)。
- **[REQ-2026-011-F07] マージメッセージの検査**: `merge-to-main.sh` は、メッセージファイルに、要件 ID(`REQ-YYYY-NNN`)、「証拠」(または `Evidence`)の見出し、「bonsai」の見出し、純増減(または `Net`)と削除したもの(または `Removed`)の語がなければ、main に触れる前に非 0 で終了し、足りない項目を示す。
- **[REQ-2026-011-F08] 共通規則の整理**: `~/.claude/CLAUDE.md` から、AGENT.md の共通規則表に移した規則(Workflow、Coding Discipline、Design & Document Accuracy、Gated Modified Waterfall)を削除し、個人情報(idea-api など)と、AGENT.md を指す 1 行だけにする。cheeze_gyudon の AGENT.md の「全体の規則は繰り返さない」の記述を、共通規則表を持つ形に直す。

## 5. 非機能
- **誤検知の抑制**: 読み取りだけの Bash(`cat`、`grep` など)で ASK を出さない。
- **失敗の向き**: ローカルのフックは助言(DEC-002)。`gov` 自身のエラー、解析できない入力、`gov` が見つからない場合は、ブロックせず通す(DEC-039。ブロックにすると、`gov` の再導入のための Bash まで止まる)。拒否するのは、規則に違反すると判定できたときだけ。
- **時間**: ASK とフックの判定は 1 秒以内。

## 6. 完了の定義
F04・F05 に対応する `02_system_tests.md` の E2E が通ること。F01 は両リポジトリの AGENT.md を読んで確認(`L1-M05`)、F07・F08 は、リポジトリの外のファイルなので手動確認(`L1-M02`、`L1-M03`)で記録する。`scripts/gate.sh` が通ること。
